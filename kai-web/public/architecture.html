Request Routing — Query Depth Model

Not all questions are equal. KAI routes based on complexity and depth of context required — not just which advisor owns it. Life is mostly gray, not black and white.

Fetch
Simple lookup or action. No context required. Just do it.

Examples: "What time is my meeting?" · "Add milk to the list" · "Ack this in Telegram"
Haiku / Local
Understand First
Needs context, dependencies, or clarification. Ask 1–2 targeted questions, then execute.

Examples: Guitar research (knows your rig) · "Find a gluten-free restaurant + make reservation" · Product research with ecosystem constraints
Sonnet
Process
Multi-step workflow. Involves a team, a delivery, a plan, or a structured output.

Examples: Marketing brief → creative team → plan → deliverable · Medical research → sourced + validated · Podcast script + upload

KAI is designed as a full life OS with 8 functional layers. Each layer has a defined role, tooling, and build phase. Not all layers are built yet — see status badges.
🖥️
Interface Layer
How Leo talks to KAI. Web dashboard, Slack DMs, Telegram, iOS Shortcut, Wispr Flow dictation, and Siri voice. Each surface has different strengths — web for visual/data, Slack for mobile/notifications, Telegram for on-the-go capture, Wispr Flow for quality dictation at any screen, Siri for hands-free.
Dashboard ✅ Slack ✅ Telegram ✅ iOS Shortcut ✅ Wispr Flow ✅ (works now, no build) Siri Shortcut — Sprint 9 Full voice layer — Sprint 10/11
🧠
AI Council Layer
8 lead advisors + 10 specialist personas. Each advisor has a defined domain, model assignment, and access to KAI tools. KAI chief is the command center — all tool-use runs through the chief. Complexity routing (Haiku/Sonnet/Opus by task type) is the next model-layer improvement.
8 advisors live ✅ 10 specialists ✅ 30 KAI tools ✅ KEYSTONE context ✅ Complexity routing — Sprint 9 Cross-advisor briefings — future
📚
Knowledge Layer
The "brain" — persistent memory that makes KAI smarter over time. Currently: vault markdown files + session summaries + decisions log. Next: Qdrant vector DB for semantic search across all vault content and conversation history. Without a proper knowledge layer, KAI doesn't get smarter — it just answers questions from scratch every session.
Vault (markdown) ✅ Session summaries ✅ Decisions log ✅ KEYSTONE.md ✅ Qdrant vector DB — Sprint 10 Semantic search — Sprint 10
⚡
Action Layer
KAI does things, not just answers questions. Integrated tools let KAI create tasks, manage projects, send Slack messages, draft emails, create calendar events, trigger n8n workflows, manage contacts, and set up entire project spaces in one command. Future: content creation pipeline (write blog post → publish to WordPress → distribute via Ayrshare), podcast automation (convert rehearsal files → upload to SoundCloud), and proactive KAI-initiated actions.
30 tools ✅ Project setup pipeline ✅ Slack T2 gate ✅ Morning brief ✅ CREATE AI content pipeline — Sprint 11 Proactive layer — Sprint 12
📊
Visualization Layer
Whenever health, sleep, harmony, task, or project data needs to be visualized, it should use consistent libraries and design language across all surfaces. Currently: dashboard widgets (Harmony score, habits, token usage, project status). Future: standardized chart library for health data (Oura sleep scores, HRV trends), mission analytics, content performance.
Dashboard widgets ✅ Token usage charts ✅ Health data visualization — post-Oura integration Standardized chart library — future
📡
Learning Layer
KAI should keep aware of the AI landscape and proactively surface relevant new capabilities, models, or tools. When something powerful and relevant to KAI's stack becomes available — KAI should tell Leo about it, not the other way around. Also includes Leo's personal learning: courses, tutorials, structured skill development. A teaching persona (local, accessible remotely) can create personalized courses — music, meditation, guitar technique.
AI landscape monitoring — future Teaching persona — future Course creation (music, meditation) — future
🔒
Security Layer
Third-party watchdog for inbound and outbound threats. What is acting as a guardian for rogue inputs, unauthorized outbound data, or compromised integrations? Candidates: Wazuh (open-source SIEM + host IDS), integrated with UniFi network (Leo has Ubiquiti) for network-level visibility. UniFi can provide traffic inspection and block at the network layer for any worker connections that look wrong.
Wazuh SIEM — future UniFi network integration — future Not yet in stack
🗄️
Data Layer
Where is the data, is it backed up, is it secure and encrypted, and is the full system documented end-to-end including the user-facing manual? Currently: vault lives on Linux worker docker volume (n8n_data equivalent — kai_vault). All conversation history, projects, harmony data, config lives there. Recovery plan and automated backup to iCloud is not yet built. Full system documentation (architecture + user manual) is the KAI_Architecture.html file (this document).

Privacy Architecture

KAI is designed with a privacy-first, local-first architecture for sensitive data. Personal health, emotional, and financial data stays on the worker whenever possible.

Local-First Advisors
Doc
Health data stays on-device
Ollama qwen2.5:3b · worker only · no cloud call · 9s/turn
Ember
Personal/emotional data local
Ollama qwen2.5:3b · insight extraction stays on worker · 9s/turn

Fallback: if Ollama is unavailable, routes to Anthropic with a note. Can be disabled to enforce local-only.

Non-Negotiable Rules
Email KAI never sends email. Ever. Always draft → Leo sends manually. Tier 3 gate.
Delete Permanent deletion requires typed confirmation. No undo.
Financial No financial access — all financial ops require explicit setup + Tier 3.
External comms Anything crossing to outside world needs Slack ✅ reaction (Tier 2).

Architectural Decisions — Locked In
1
Anthropic-only cloud
OpenAI dropped. Unified billing, better quality, simpler stack. Biz advisor moves to claude-sonnet-4-6.
2
Route by task type, not advisor
Haiku for simple, Sonnet for work, Opus for decisions. Complexity classifier on council API.
3
Local-first for privacy advisors
Ember + Doc always local. Mac Mini M4 is the hardware upgrade path for better local models.
4
Web search as a layer
Tavily for automated flows ($0.01/search). Perplexity for on-demand deep research ($20/month).
5
Gray-area query depth
Three modes: Fetch (just do it), Understand First (ask 1–2 questions), Process (multi-step workflow). Life is lived in the gray — KAI must understand the question, not just look for keywords.
6
Slack bidirectional logging
Leo's messages in Slack aren't captured in vault history — only AI replies. Full bidirectional logging is a future improvement for complete records.
7
Voice stack: whisper.cpp + OpenAI TTS
STT: local whisper.cpp (free, API quality). TTS: OpenAI TTS API (~$0.01/response) or Kokoro local (free). Wispr Flow covers quality dictation at any screen today at zero build cost. Siri Shortcut covers hands-free. Full two-way audio is Sprint 10.
