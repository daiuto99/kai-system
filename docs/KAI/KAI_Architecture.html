Privacy Architecture

KAI is designed with a privacy-first, local-first architecture for sensitive data. Personal health, emotional, and financial data stays on the worker whenever possible.

Local-First Advisors
Doc
Health data stays on-device
Ollama llama3.2 · worker only · no cloud call
Ember
Personal/emotional data local
Ollama llama3.2 · insight extraction stays on worker

Fallback: if Ollama is unavailable, routes to Anthropic with a note. Can be disabled to enforce local-only.

Non-Negotiable Rules
Email KAI never sends email. Ever. Always draft → Leo sends manually. Tier 3 gate.
Delete Permanent deletion requires typed confirmation. No undo.
Financial No financial access — all financial ops require explicit setup + Tier 3.
External comms Anything crossing to outside world needs Slack ✅ reaction (Tier 2).

Mission Delegation (COO Mode)

Leo grants KAI temporary full autonomy with a defined scope and return trigger. KAI executes everything within Tier 1, logs all actions, and delivers a structured briefing on return. Tier 2/3 rules never relax during missions.

Things to Consider

OpenAI API key

2
Context window management
Long-running channels will hit limits. Rolling window or summarization strategy needed for chief channel
3
Specialist pool expansion
Current 10 specialists are lead advisors. KAI can invoke them but can't loop or collaborate autonomously yet
4
Slack bidirectional logging
Leo's messages in Slack aren't captured in vault history — only AI replies. Full bidirectional logging would complete the record

Cost control at scale
$0.17 all-time so far. As scheduled briefs scale, consider per-advisor daily budgets and spend alerts
6
Local model quality
llama3.2 is solid for conversational use but weaker than Claude for complex reasoning. Monitor Doc/Ember quality and upgrade model as needed
